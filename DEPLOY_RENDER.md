# Deploy Smart Mentor Connect on Render (3 steps)

One GitHub repo -> three websites (management, teacher, student) + MySQL.
Each site gets its own URL, e.g. `smart-mentor-teacher.onrender.com`.

## Step 1 - Push the project to GitHub
Push this whole folder (the one containing `render.yaml`) to a new GitHub repo.
`.env` and `shared/face_ids/` are git-ignored on purpose.

## Step 2 - Create ONE environment group with your secrets
Render dashboard -> **Environment Groups -> New Environment Group**.
Name it exactly **`smart-mentor-secrets`** and add:

| Key | Value |
| --- | --- |
| `GEMINI_API_KEY` | your Google Gemini key (teacher AI assistant) |
| `ADMIN1_EMAIL` | Gmail address that sends e-mails |
| `ADMIN1_APP_PASSWORD` | that Gmail's Google **App Password** |
| `ADMIN2_EMAIL` | second sender Gmail |
| `ADMIN2_APP_PASSWORD` | its App Password |

All three sites read these, so you type them once. (Secret keys and the
database password are generated by Render automatically.)

## Step 3 - Deploy
Render dashboard -> **New -> Blueprint** -> choose your repo -> **Apply**.

This creates:
* `smart-mentor-db` - MySQL (private service with a 1 GB disk; has no free tier, about the price of a Starter instance - check Render pricing)
* `smart-mentor-management`, `smart-mentor-teacher`, `smart-mentor-student` - free web services in the Singapore region

Wait for all four to show **Live**, open the **management** URL and register
your college. Tables are created automatically. Then add teachers/students and
log in on the other two sites, choosing the same college.

---

## Want it free? Use your own MySQL instead
Render does not host free MySQL. If you would rather use a free hosted MySQL
(Aiven, TiDB Cloud, etc.):

1. Add one more key to the `smart-mentor-secrets` group:
   `DATABASE_URL = mysql+pymysql://USER:PASSWORD@HOST:PORT/DBNAME`
   (add `?ssl_ca=/etc/ssl/certs/ca-certificates.crt` if SSL is required). The user must be allowed to `CREATE DATABASE`
   because every college gets its own database.
2. When creating the Blueprint, set the file path to
   `deploy/render-free-external-db.yaml` (or copy it over `render.yaml`).

## Deploying one site by hand with Docker
The repo root now has a `Dockerfile`, so Render's **New -> Web Service -> Language: Docker** works too.
One image serves all three sites: add an environment variable `SIDE` = `management`, `teacher` or `student`
(plus the keys from Step 2, a `*_SECRET_KEY`, and either `DATABASE_URL` or `MYSQL_*`). Repeat per site.
`docker compose up --build` runs all three plus MySQL locally.

## Things to know
* **One worker per site** (`-w 1 --threads 4`) is intentional: login lockouts and background e-mail job status live in memory.
* **Free web services sleep** after ~15 minutes idle; the first visit wakes them (about a minute).
* **E-mail:** to my knowledge Render's free web services block outbound SMTP (ports 25/465/587), which Gmail uses, so OTP/result e-mails fail on the free plan. Check Render's current docs; a paid web instance avoids this.
* **Face ID photos** are wiped on each redeploy unless you attach a persistent disk to that site (paid) and set `FACE_ID_DIR=/var/data/face_ids` with mount path `/var/data`. Password login is unaffected.
* **Updating:** push to GitHub; Render redeploys automatically.
* **Local use** is unchanged: see `.env.example` and `run_*.py`.
